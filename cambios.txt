Resultado:

El menú ahora es un componente reutilizable. Cualquier cambio
futuro solo necesita hacerse en menu.php y se reflejará

CAMBIOS REALIZADOS (decimotercera modificación - Corrección de signos � en perfiles)
=============================================================================

Fecha: 01/10/2026

Descripción:
En la página de perfiles aparecían signos raros (�?�) en vez de
tildes y separadores. Dos causas:

1. Varios archivos estaban guardados en codificación Latin-1
   (Windows-1252) mientras el sitio declara UTF-8, por lo que
   los acentos se veían como �.
   Se convirtieron a UTF-8 (sin BOM):
   - menu.php, conexion.php, css/styles.css, js/buscar.js,
     js/registro.js, codigos.txt

2. Dos caracteres estaban corrompidos en el código fuente
   (sus bytes originales se habían perdido):
   - oficios.php (línea 126): separador entre oficio y sector,
     restaurado a "•" (ej: Gasfitero • Ñuñoa).
   - admin.php (línea 125): columna Destacado, restaurado a
     ⭐ para destacado y — para no destacado.

Archivos modificados:
---------------------
1. oficios.php
2. admin.php
3. menu.php
4. conexion.php
5. css/styles.css
6. js/buscar.js
7. js/registro.js
8. codigos.txt (también regenerado con el código actualizado
   de los 14 archivos del proyecto)

Resultado:
----------
Todos los archivos del proyecto son UTF-8 válidos y ya no
aparecen signos � en los perfiles ni en el resto del sitio.

CAMBIOS REALIZADOS (vigésima séptima modificación - Arreglo del menú desplegable)
==================================================================================

Fecha: 02/10/2026

Descripción:
El menú desplegable (offcanvas de Bootstrap 5) no funcionaba
correctamente. Al hacer clic en el botón hamburguesa, el menú no
se abría o se abría pero no se veía correctamente.

Causas identificadas:
--------------------
1. El offcanvas no tenía aria-hidden="true" cuando estaba cerrado,
   lo que podía causar problemas de accesibilidad y visualización.
2. El offcanvas no tenía data-bs-backdrop="true", por lo que el fondo
   no se oscurecía y podía confundir al usuario.
3. El offcanvas no tenía data-bs-keyboard="true", por lo que no se
   podía cerrar con la tecla Escape.
4. El CSS del offcanvas no tenía position: fixed ni z-index definido,
   lo que podía causar problemas de superposición con otros elementos
   como el cl-hero::after que tiene position: absolute.

Cambios aplicados:
------------------
1. menu.php:
   - Se agregó aria-hidden="true" al offcanvas.
   - Se agregó data-bs-backdrop="true" para que el fondo se oscurezca.
   - Se agregó data-bs-keyboard="true" para poder cerrar con Escape.
   - Se agregó data-bs-scroll="false" para evitar scroll en el body.

2. css/styles.css:
   - Se agregó position: fixed al .cl-menu para asegurar que el
     offcanvas se posicione correctamente en la pantalla.
   - Se agregó z-index: 1050 al .cl-menu para asegurar que el
     offcanvas esté por encima de otros elementos (el z-index por
     defecto de Bootstrap para offcanvas es 1045, pero al usar
     100vw de ancho y position: absolute en el hero, se necesitaba
     un z-index más alto).

Resultado:
----------
El menú desplegable ahora funciona correctamente:
- Se abre al hacer clic en el botón hamburguesa.
- El fondo se oscurece cuando el menú está abierto.
- Se puede cerrar con la tecla Escape.
- Se puede cerrar haciendo clic en el botón X o en cualquier enlace.
- El menú se muestra por encima de todos los demás elementos.

CAMBIOS REALIZADOS (trigésima segunda modificación - Arreglo de la tarjeta de destacados)
===========================================================================================

Fecha: 02/10/2026

Descripción:

la mitad y mostraba un error fatal en vez de la tarifa. El resto de
la tarjeta (botón "Ver perfil") quedaba sin renderizar.

Causa identificada:
------------------
index.php usaba number_format() sobre el campo tarifa, que es un
VARCHAR de texto libre y no un número. El campo se llena desde un
<input type="text"> con placeholder "Ej: Desde $15.000 la visita", y
solo se valida que tenga 3 caracteres o más, así que contiene valores
como "Desde $15.000 la visita", "$8.000 por hora" o
"Presupuesto sin costo".

Con PHP 8, number_format() exige float, así que al recibir un string
lanza:
  Fatal error: Uncaught TypeError: number_format(): Argument #1
  ($num) must be of type float, string given in index.php:210

index.php era el ÚNICO archivo que hacía esto. admin.php, oficios.php
y perfil.php ya mostraban la tarifa con htmlspecialchars(), que es lo
correcto.

Cambios aplicados:
------------------
1. index.php (línea 210)
   - Se reemplazó:
       Tarifa: $<?= number_format($t['tarifa'], 0, ',', '.') ?>
     por:
       Tarifa: <?= htmlspecialchars($t['tarifa']) ?>
   - Se quitó el "$" fijo del marcado porque la tarifa ya lo trae en
     su texto y se estaba duplicando.

2. codigos.txt - Se regeneró.

Resultado:
----------
Las tarjetas de destacados muestran la tarifa completa y ya no
cortan la página con un error fatal.

Nota: los demás number_format() del proyecto se usan sobre "promedio",
que sí es un número (viene de AVG()), y no se tocaron.

Los campos de contraseña (iniciar sesión y crear cuenta) solo mostraban

   - Es genérico: sirve para cualquier campo de contraseña futuro, solo
     hay que añadir el atributo data-ver-contrasena="id-del-input" al
